# 看房日记 · 首版产品设计

设计日期：2026-10-10。当前阶段进入手机网页交互原型开发，确认交互后再封装安卓；网页原型与安卓首版的能力差异见第 8 节。

## 1. 定位与已确认范围

个人使用、离线记录优先的安卓看房日记。核心流程：选择买房或租房 → 新建房子 → 现场分区拍照和记笔记 → 复看补充 → 对比候选房子。

买房与租房分别管理，共用图文记录结构。定位、小区配套、交通、户型、整屋情况、各房间、物业费、取暖、网费、家具情况、养宠物约定均纳入首版。

### 首版必做

- 买/租双模式、房源、看房日记、分区图文、费用与约定、对比看板。
- 房源渠道与联系人：中介 / 房东直租（买房为业主直售），记录联系人姓名和电话。
- 买房产权与税费：房龄、产权性质与年限、满五唯一、税费金额记录。
- 水电燃气：民用 / 商用及单价、缴费方式。
- 本地完整备份导出/导入（换机、卸载会丢数据，见第 5 节）。
- 固定月支出参考（规则见“费用与约定”）。

### 首版不做

房源推荐、交易撮合、贷款计算、税费自动计算（只记录中介或材料给出的金额）、聊天与通讯、家庭协作、账号、云同步、离线地图、OCR、语音备忘与语音转文字。

### 核心设计原则

1. **事实与观察分离**：房源级“事实”（价格、面积、户型、产权、费用、约定）只保存一份最新值；每次看房的“观察”按日记保存，永不覆盖。
2. **未知不等于零**：未确认、缺失与“没有 / 不允许 / 免费 / 0 元 / 民用”严格区分，任何页面都不自动补值。
3. **来源可见**：约定、费用、产权记录确认来源，口头说法不视为已核实。
4. **不替用户下结论**：不生成综合评分或“最佳房源”。

## 2. 页面和操作流程

### 入口

- 首次进入展示“我要买房”“我要租房”两个入口。
- 之后记住上次选择，进入对应房源列表；顶部始终可以切换。
- 两个模式的房源和对比候选互相隔离，避免总价和月租混在一起。

### 房源列表

- 一张卡片展示：封面、房源名称、价格、面积、户型、渠道（中介 / 直租或直售）、最新看房日期、个人结论。
- 个人结论：待考虑 / 心仪 / 已排除。“已排除”可选填一句排除原因，方便日后回看。
- 默认按最新看房日期倒序；支持按结论筛选，“已排除”默认折叠到列表底部，不删除。
- 记录完整度（例如“费用 3 项未确认”）与个人结论分开展示，不用未记录的信息判定好坏。
- 主操作为“新建房子”，底部入口为“房源”“对比”“设置”。
- 空状态直接展示“记录第一套房子”。

### 新建房子

- 必填仅房源名称；价格、面积、户型、地址、渠道等可以稍后补充。
- 名称可用“小区名 + 楼栋房号”，也可直接写自定义别名。
- 地址支持手动填写、获取当前位置、地图选点。当前定位需要用户确认对应房子位置。
- 没有定位权限或没有网络时仍可保存；离线地图/地址搜索不是保存记录的前提。
- 买房填总价（万元），租房填月租（元/月）。
- 面积需注明口径：建筑面积 / 套内面积 / 使用面积 / 未确认；买房在填写总价和面积后派生显示单价，并标注口径。
- 可顺手选择渠道并添加一位联系人（选填），方便现场留电话。
- 保存后直接进入第一篇看房日记。

### 房源详情

分为“基本信息”“看房日记”“费用与约定”三个页签。顶部展示核心事实、渠道与主要联系人的一键拨号，以及“新增看房日记”。

- **基本信息**：价格、面积及口径、户型（几室几厅几卫）、楼层/总楼层、电梯、朝向、地址、封面、户型图、空间列表；买房另含产权信息。
- **渠道与联系人**：见下文。
- **空间列表**：房源级维护主卧、次卧、主卫等具体空间。新建日记时沿用已有空间，也可现场新增；重命名空间不影响历史记录和对比。
- 封面默认取第一张照片，可手动更换为任意一张已有照片。

### 渠道与联系人

- 渠道四选一：中介 / 房东直租（买房显示为“业主直售”）/ 其他 / 未确认。
- 联系人可添加多位，每位记录：角色（中介 / 房东或业主 / 其他）、姓名或称呼、电话、中介公司与门店（选填）、备注（如“周末才能看房”）。
- 点电话调起系统拨号盘，长按复制；应用不申请电话和通讯录权限，首版不从通讯录导入。
- 渠道只是事实记录：选择“房东直租”不会自动把中介费记为 0 元，中介费仍按费用规则单独记录。

### 看房日记

每篇看房日记有自己的看房时间、总体印象、优点、顾虑，以及下列图文分区。分区只记录本次观察；其中涉及房源事实的项（面积、朝向、取暖方式等）以提示形式出现，填写后询问“是否同步更新房源信息”，由用户决定。

| 分区 | 观察提示 | 图文内容 |
| --- | --- | --- |
| 小区配套 | 商超、医疗、绿化、停车、公共设施 | 小区照片和观察 |
| 交通 | 地铁/公交站及步行时间、到各通勤目的地的时间 | 路线观察；注明手动记录或地图估算 |
| 户型 | 实际布局、动线、与户型图是否一致 | 户型图和布局感受 |
| 整屋情况 | 装修、采光、通风、噪音、异味、潮湿、取暖实际情况、家具家电概况、电表水表类型 | 整体照片和综合描述 |
| 卧室 | 大小、朝向、采光、隔音、收纳 | 每个卧室各自的照片和笔记 |
| 厨房 | 空间、通风、燃气/电、台面、设备状态 | 厨房照片和笔记 |
| 卫生间 | 干湿分离、通风、热水、排水、异味 | 每个卫生间独立记录 |
| 客厅 | 大小、采光、布局、噪音 | 客厅照片和笔记 |
| 其他空间 | 阳台、储物间等自定义名称 | 自定义空间图文 |

- 卧室、卫生间等可对应多个空间实例，例如“主卧”“次卧”“主卫”。
- 通勤目的地（公司、学校等）在“设置”中统一维护，所有房源按同一组目的地记录，保证可比。每次看房的通勤记录以目的地 ID 关联，记录交通方式、分钟数、来源及看房时间；不同方式单列，未知耗时不填 0。已有记录的目的地可重命名，删除前提示并同步删除其通勤记录，不留下无效引用。
- 每个分区支持多张照片、多段文字；每张照片支持说明。照片支持拍摄和从相册选择。
- 不要求填完所有分区，不强迫逐项打分；推荐“简短评价 + 照片 + 文字”。
- 编辑即自动保存，没有“发布/提交”步骤。复看新增日记，不覆盖旧照片和观察。自动保存的完成状态和恢复边界见第 4 节。
- 看房时间可修改；日记可删除（二次确认，连同其照片）。

### 费用与约定

以下为房源级事实，跨日记共享并用于对比；每项保留最近更新时间和确认来源（现场观察 / 房东或中介口述 / 合同或材料 / 未确认）。

| 信息 | 记录方式 | 对比方式 |
| --- | --- | --- |
| 物业费 | 金额、计费周期、按面积或按套、是否包含、承担方、备注 | 显示原金额与单位，避免每平方米月费与每套月费直接比 |
| 取暖 | 集中供暖 / 自采暖 / 空调 / 其他 / 未确认；费用、周期、是否包含 | 分别对比方式和费用；缺失费用标为未确认 |
| 网费 | 是否已开通、是否包含、金额、周期、运营商/网速（选填） | 同时展示包含状态和费用 |
| 水电燃气 | 水、电、燃气各自：民用 / 商用 / 未确认；单价（选填）；缴费方式（自行缴费 / 房东代收 / 包含在房租 / 未确认） | 展示民商用状态与单价；商用项醒目标注 |
| 家具家电 | 无 / 部分配备 / 配备较全 / 未确认；清单、完好情况、是否随租/随售 | 展示清单与缺少/损坏项，可关联已有照片 |
| 养宠物 | 允许 / 不允许 / 有条件 / 未确认；条件说明 | 直接展示四态与条件，例如“允许猫，需额外押金” |
| 租房条款（租房） | 押金（月数或金额）、付款方式（如押一付三）、租期、中介费等一次性费用 | 押金和一次性费用单列，不计入每月开销 |
| 产权信息（买房） | 见下文 | 房龄、产权性质与剩余年限、满五唯一并列展示 |
| 交易税费（买房） | 见下文 | 作为一次性支出单列，标注来源 |
| 其他费用 | 自定义名称、金额、周期、是否包含 | 与其他费用同规则展示 |

- 家具家电清单预置床、衣柜、沙发、桌椅、空调、冰箱、洗衣机、热水器、灶具，允许添加其他项。首版只做清单及状态，不做资产管理。
- 费用状态四选一：已知金额 / 已包含在房租或房价中 / 免费 / 未确认。不填默认“未确认”，不等于 0。
- 周期：月、季、年、采暖季、一次性。
- 水电燃气单价单位固定：水 元/吨、电 元/度、燃气 元/立方米。未填计价类型时显示“未确认”，不默认为民用。

**产权信息（买房）**

- 建成年份 → 派生显示房龄；年份未知时房龄显示“未确认”。
- 产权性质：商品房 / 房改房 / 经济适用房 / 商业或公寓 / 其他 / 未确认。选择“商业或公寓”时提示核对水电燃气是否为商用。
- 产权年限：70 年 / 50 年 / 40 年 / 其他 / 未确认，可填起始年份并派生剩余年限。
- 满五唯一拆成两项分别记录：卖方持有年限（满五年 / 满两年不满五年 / 不满两年 / 未确认）、是否卖方家庭唯一住房（是 / 否 / 未确认）。界面汇总显示为“满五唯一 / 满五不唯一 / …”，任一项未确认则整体显示“未确认”。

**交易税费（买房）**

- 只记录，不自动计算：税费规则因城市、首套/二套、面积、满五唯一等而不同且会调整，应用不内置计算公式，避免给出错误金额。
- 预置税费项：契税、增值税及附加、个人所得税、中介费、其他；每项按费用规则记录状态、金额、承担方（买方 / 卖方 / 未确认）和来源（中介估算 / 合同或材料 / 自己估算）。
- 汇总显示“买方已知一次性税费 ¥X + N 项未确认”，与房价分开，不计入固定月支出参考。

**固定月支出参考**（只做参考，不叫“总成本”）：

- 只换算金额、周期、计费单位、承担方均明确，且承担方为自己的固定费用。按面积计费必须另外填写实际计费面积，不自动使用房源展示面积；计费面积缺失时该费用为未确认。
- 先将按面积单价乘以实际计费面积，再按周期换算：月费直接使用、季度费用除以 3、年费除以 12。采暖季费用按每年一个采暖季的金额除以 12，注明“按一年一季摊销，非实际月账单”；若不能确认该收费频率，保留为未确认，不换算。
- 已包含的费用不重复计算；押金、税费、中介费等一次性费用不计入。
- 水电燃气按用量计费，不计入参考值，只在旁边提示民商用状态。
- 未填写的费用、已知单价但缺少计费面积、承担方或周期未确认均计入未确认项；明确由他人承担的费用不计入自己的费用。只要存在未确认的固定费用，结果显示为“已知部分 ¥X/月 + N 项未确认”，不能展示成完整数字。
- 租房参考值 = 月租 + 上述固定费用；月租未填写也计为一项未确认，不当作零元。买房只汇总持有期固定费用，不含房价、税费和贷款。中间计算保留精度，展示时四舍五入到分。

### 对比看板

- 同一模式下对比候选可保存 0–4 套房子，达到 2 套才显示对比；从房源列表多选或在房源详情中“加入对比”。对比选择在下次打开时保留；删除房源后不足 2 套时展示补选提示。
- 安卓窄屏同屏展示两列，更多房源横向滑动，固定维度列和房源标题。
- 顶部：价格（买房含单价）、面积及口径、户型、渠道、最新看房日期、个人结论、固定月支出参考。
- 核心维度：位置、交通/通勤、小区配套、整屋情况、取暖、物业费、网费、水电燃气、家具家电、宠物约定。
- 买房另含：房龄、产权性质与剩余年限、满五唯一、买方一次性税费；租房另含：租房条款。
- 房间维度：户型、卧室、厨房、卫生间、客厅等；按空间类型汇总，展开后看主卧/次卧等具体空间。
- 联系人不参与对比，点房源标题可进入详情拨号。
- 照片可以按相同分区对照；点单元格查看对应图文与记录时间。
- 观察类内容默认取该分区（或该空间）看房时间最新且有文字或照片的日记，并显示看房日期；按看房时间而不是编辑时间选择，今天补写旧日记不会替代较新的观察。相同看房时间按日记创建时间、ID 确定稳定顺序。只有照片的观察也可以参与对比；该分区整体取同一篇日记，避免混拼不同时间的文字和照片。
- 事实类内容使用房源最新已保存值；不同日记中的矛盾描述保留历史，由用户决定是否更新房源信息。
- 未确认或缺失项统一显示“待补充/未确认”，不自动补成 0、无、允许、民用或差评。
- 买房不展示租房条款；租房不展示总价、单价、产权与税费。

### 设置

- 默认模式（买房/租房）。
- 通勤目的地管理（名称、地址）。
- 备份导出 / 导入，显示上次备份时间。
- 本地存储占用（照片占大头），以及卸载会清除数据的提示。

## 3. 最小数据结构

| 对象 | 关键内容 | 关系 |
| --- | --- | --- |
| 房源 House | ID、买/租类型、名称、地址、坐标、价格及单位、面积及口径、户型、楼层/总楼层、电梯、朝向、渠道、封面照片 ID、户型图照片 ID、结论、排除原因、创建/更新时间 | 一套房多个空间、日记、费用项、联系人 |
| 联系人 Contact | ID、房源 ID、角色、姓名或称呼、电话、公司与门店、备注、排序 | 一套房多位；不跨房源共享 |
| 空间 Space | ID、房源 ID、类型（卧室/厨房/卫生间/客厅/其他）、名称、排序 | 跨日记稳定，对比按它对齐 |
| 看房日记 Visit | ID、房源 ID、看房时间、总体印象、优点、顾虑、创建/更新时间 | 一篇日记多个分区记录 |
| 分区记录 SectionNote | ID、日记 ID、分区类型、空间 ID（房间类分区必填）、观察提示项、文字、更新时间 | 同一日记中主卧、次卧为不同记录 |
| 照片 Photo | ID、所属分区记录 ID（或房源 ID，用于户型图等房源级照片）、本地原图路径、缩略图路径、说明、排序、拍摄时间 | 照片只归属一处；其他地方按 ID 引用 |
| 费用项 Expense | ID、房源 ID、类别（预置/自定义，含税费、中介费）、名称、费用状态、金额、计费单位/周期、实际计费面积、承担方、备注、来源、更新时间 | 物业费、取暖费、网费、税费、租房一次性费用等 |
| 水电燃气 Utility | 房源 ID、类型（水/电/燃气）、计价（民用/商用/未确认）、单价、缴费方式、来源、更新时间 | 一套房每种类型一条 |
| 房屋约定 HouseTerms | 房源 ID、取暖方式、家具家电状态与清单（可引用照片 ID）、宠物四态及条件、押金、付款方式、租期、各项来源、更新时间 | 一套房一条 |
| 产权信息 Ownership | 房源 ID、建成年份、产权性质、产权年限、产权起始年份、卖方持有年限、是否唯一住房、各项来源、更新时间 | 仅买房，一套房一条 |
| 通勤目的地 CommuteTarget | ID、名称、地址、坐标 | 全局，交通分区按它记录时间 |
| 通勤记录 CommuteRecord | 日记 ID、目的地 ID、交通方式、耗时分钟数、记录来源 | 每篇日记每个目的地和方式最多一条，随日记保存 |
| 对比集 CompareSet | 买/租类型、房源 ID 列表（0–4） | 每个模式一份，只存 ID 不复制资料；至少两套才展示对比 |

- 面积、金额、坐标、年份等未知数据允许为空，不使用 0 占位；枚举字段一律包含“未确认”，并作为默认值。
- 房龄、剩余产权年限、单价均为派生值，不单独存储。
- 删除照片前检查是否被封面、户型图、家具清单引用；被引用时提示并解除引用。
- 删除房源时级联删除联系人、空间、日记、分区记录、照片文件、费用、水电燃气、约定和产权信息，并从对比集移除。

## 4. 离线与安卓交互原则

- 保存日记不依赖网络；列表、图片、对比均读取本地数据。
- 添加照片后复制到应用自有存储，避免原相册清理后笔记失图；列表与对比使用缩略图。
- 编辑后立即发起本地保存，页面显示“保存中 / 已保存 / 保存失败”。只有本地事务完成才显示“已保存”；已完成保存的内容在刷新或进程被回收后恢复。突然终止时尚未完成的写入不承诺恢复。切换分区、日记、房源及导出/导入前等待当前保存完成；保存失败时保留当前编辑内容并提供重试，不静默丢弃。照片在文件与关联数据全部保存后才显示为已保存。
- 仅在点击定位、拍照、选图时请求相应权限；拒绝后仍可手写记录，并给出去系统设置开启的入口。拨号使用系统拨号盘，不申请电话权限。
- 定位只获取用户主动请求的位置；地图搜索、反向地理编码需要网络时明确说明，允许手动完成。
- 删除房源、日记前二次确认，并说明会一并删除的照片数量。
- 第一版不依赖云服务；技术栈和地图供应商在进入开发时再确定。

## 5. 备份与恢复

- 导出为单个压缩包：结构化数据（JSON，含数据格式版本号）+ 原图；缩略图导入后重新生成。
- 通过系统分享/文件选择器保存到用户选择的位置，应用不申请全盘存储权限。
- 导入首版只支持“全量替换”：导入前提示会覆盖当前数据，并建议先导出当前数据。合并导入留待后续。
- 导出先取得结构化数据和所引用原图的一致快照，再生成压缩包，避免导出期间编辑导致图文不匹配；备份包含每张图片的大小与校验摘要。
- 导入前校验版本、完整性、图片校验摘要与关联关系；先在暂存区准备新数据，全部准备好后再原子替换。校验失败、空间不足或导入中断时不留下半套数据，原有数据保持完整；导入成功前不删除旧数据。
- 导出时提示备份包含联系人电话，照片可能含拍摄位置信息，请妥善保管，不要随意分享。
- 超过 30 天未备份且有新记录时，在设置入口给出轻提示，不弹窗打扰。

## 6. 首版验收场景

1. 买房和租房可切换，房源和对比集互不串组；新建时价格字段对应正确单位。
2. 仅填名称也能建房，无定位权限和离线情况下也能完整记录。
3. 同一房源新增两篇日记，旧记录和照片仍可查看；对比中观察类内容标注来源日记日期。
4. 可分别记录主卧、次卧，各自保存多张照片和文字；重命名“次卧”后历史记录与对比仍正确对应。
5. 日记中修改朝向等事实项时，只有用户确认后才更新房源信息。
6. 整屋情况独立于房间记录；家具、取暖、物业费、网费、水电燃气、宠物条件、租房条款可保存并进入对比。
7. “宠物未确认”不会展示为允许；“费用未确认”不会展示为零元；“水电未确认”不会展示为民用。
8. 两套房可按相同维度比较，单位与面积口径清楚；点摘要能回到相应日记和照片。
9. 已含费用不重复计入参考月支出，押金、税费等一次性费用和水电燃气不计入；存在未确认固定费用时参考值显示“已知部分 + N 项未确认”。
10. 房源可记录渠道和多位联系人，点电话调起系统拨号盘；选择“房东直租”后中介费仍为未确认而非 0 元。
11. 买房填写建成年份后显示房龄；持有年限或唯一住房任一项未确认时，满五唯一显示“未确认”；税费按来源记录并单列，不计入月支出参考。
12. 编辑日记并等到“已保存”后强制结束应用，重新打开内容一致；保存失败显示可见错误，不显示虚假的已保存状态。
13. 删除房源后，其照片文件和联系人被清理，对比集中不再出现该房源。
14. 备份导出、清空数据后重新导入，房源、联系人、空间、日记、照片、费用、产权及引用关系一致；导入损坏文件、图片缺失、关联无效或空间不足时现有数据不受影响。
15. 按面积费用缺少实际计费面积时不参与月费合计；季度费用正确除以 3；月租未知时显示未确认项。
16. 补写旧看房日记不会覆盖对比中较新看房的观察；删除对比候选后只剩一套时可正常保存并提示补选。

## 8. 原型范围

手机网页原型位于 `prototype/`，用于验证记录与对比流程。支持本地保存文字、照片、房源事实、联系人、通勤、费用与买房信息，以及 ZIP 完整备份和恢复；示例数据需用户主动载入，不与真实记录混入。

网页以浏览器本地存储实现离线数据保存，localhost / HTTPS 完整加载并缓存后可离线重新打开；普通内网 HTTP 加载后可断网编辑，但不支持离线重开页面。清除浏览器网站数据、更换浏览器或设备可能丢失本地记录，应先导出备份。浏览器定位需要权限及安全访问环境；内网普通 HTTP 地址不可自动定位，仍可手写地址和坐标。原型不集成在线地图选点，不生成安卓 APK；拍照能力由手机浏览器与系统文件选择器提供。安卓原生存储、定位权限与 APK 安装将在交互确认后的安卓阶段实现。

## 9. 安卓首版实现

工程位于 `android/`，打包时将已确认的页面、样式和依赖嵌入安装包。页面通过受限本地 HTTPS 来源访问原生桥接；应用不依赖网页服务器、不声明互联网权限。Android 8.0 起支持安装，实际界面能力还取决于系统 WebView 版本。

记录通过 SQLite 事务保存，照片使用应用私有文件与缩略图缓存。导出固定状态与照片映射快照，快照释放前不会清理被引用原图。导入先完成字段、关联与 SHA-256 校验，再暂存照片并事务替换数据库；旧照片在提交成功后清理。重开应用时清理无引用的残留照片暂存文件。

相机使用外部系统拍照界面，相册与 ZIP 通过系统文件选择器读取/保存，不申请全盘存储权限。获取位置时请求前台定位权限，显示定位精度并由用户确认；设置提供系统应用权限入口。地图选点、反向地址解析、云同步和语音继续不纳入首版。

0.1.1 补充：房源整张卡片可进入继续编辑，对比勾选独立；原生外层容器避让状态栏、刘海、底部导航与键盘。新建房源、房源基本信息及通勤目的地均可主动获取手机位置，通勤坐标为可选字段，兼容原有无坐标记录。完整 GPS 坐标可手动带入高德地图导航，自动填充名称和终点，高德自行以当前位置作为起点；地址文字仍由用户填写。高德调用遵循[官方导航接口](https://lbs.amap.com/api/amap-mobile/guide/android/navigation)，手机 GPS 坐标使用 `dev=1`，避免坐标偏移设置错误。

首版提供调试签名的安装体验包；大量原图备份在内存中处理，受设备内存限制。验收步骤及自动检查边界见 `docs/安卓首版验收.md`。发布签名与应用商店交付不属于本次安装体验包范围。
