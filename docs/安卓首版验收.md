# 安卓首版验收

首版使用个人离线模式；不提供账号、云同步、在线地图选点和语音备忘。蓝白色界面与已确认的网页原型一致。安装体验包时使用同一包覆盖更新，卸载前先导出备份。

## 设备体验

1. 首次打开选择买房或租房，创建一套仅填名称的房源；退出应用后重新打开，检查默认模式和房源。
2. 在整屋、小区配套、交通、户型、卧室、厨房、卫生间、客厅分别输入文字；创建第二个卧室并重命名，确认各空间记录独立。
3. 使用“拍照”和“选择照片”添加原图，为照片添加说明、设置封面与户型图；退出重开并查看。删除相册中原照片后，应用记录仍可查看。
4. 新建复看日记，补写旧日记，确认对比摘要取较新看房的观察，旧日记与照片继续保留。
5. 保存物业费、采暖费、网费、家具清单、宠物条件、水电燃气及租房条款；未知金额保持“未确认”，不能误显示为免费。
6. 买房模式补充产权与交易费用。切换买租，检查房源及最多四套对比候选互不串组，比较单位对应正确。
7. 点击定位并拒绝权限，确认仍能手写地址和坐标；从设置的系统入口打开定位权限，再获取位置，核对精度提示并确认坐标。室内无定位或超时应显示可理解的提示。
8. 添加房东/中介联系人，点击电话进入系统拨号盘；不会直接拨打。
9. 设置中导出 ZIP 到手机“下载”等目录。取消文件选择时，不应更新上次备份时间；保存成功后显示新的时间。
10. 修改记录，再导入刚导出的 ZIP，确认全量替换提示和恢复结果；房源、费用、联系人、日记、原图和封面引用均恢复。网页原型导出的 ZIP 也应可导入安卓。
11. 用缺少照片、修改过照片内容或字段非法的 ZIP 导入，确认提示失败，现有记录仍完整。
12. 关闭 Wi-Fi 与移动数据，重新打开应用，查看、记录、拍照、比较及备份均可操作；当前位置取决于设备定位服务。
13. 删除一张封面照片，封面引用同时解除；删除房源后，其日记、照片、联系人和对比候选一起删除。
14. 编辑长文字并等待“已保存到本机”后强制停止应用再打开，内容应一致。保存失败时不得显示“已保存”，修复空间不足等原因后点击重试。
15. 检查系统返回键：先关闭照片/编辑弹窗，再从详情返回列表；列表返回退出。旋转设备后不丢失正在查看的页面和已经保存的数据。

## 自动验证范围

- Node：业务计算、备份字段与关联校验、原生桥接路由、二进制转换、取消/错误回调。
- Edge：完整网页流程、原图持久化、ZIP 往返、非法备份拒绝、离线页面、窄屏布局。
- 原生桥接模拟：安卓界面分支、图片选择、ZIP 快照与暂存导入、失败导入保留数据、返回键、取消导出。
- Android Instrumentation：SQLite/文件写入、备份快照文件保留、失败与成功导入，以及真实 WebView 资源与桥接加载。需连接设备或启动模拟器执行，编译测试包不等于已在设备执行。

## 0.1.5 现场录像与 MP4 播放修复（2026-10-12）

1. 打开整屋、房间或基本信息配套分区，点击“现场拍视频”，确认系统相机进入录像。录制并确认后，视频出现在当前房源、看房日期和分区，播放并补充说明；关闭应用后重开检查恢复。
2. 取消录像应返回原页面，不增加空记录；系统返回成功但未提供视频文件时显示错误。原“现场拍照”和“照片／视频”选择入口继续可用。网页端录像使用 `capture="environment"` 提示，具体系统相机行为由手机浏览器决定。
3. 更新后直接播放此前已添加的 MP4，向后和向前拖动进度。覆盖安装保留原记录，不需要重新添加视频。手机实际录像界面及小米故障原视频仍需实机检查。

- 在 0.1.4 的真实 API 35 WebView 复现：约 2 MB 的 H.264/AAC MP4，元信息位于文件末尾；首次 `bytes=0-` 请求成功，随后非零起点请求反复 `net::ERR_FAILED`，最终出现 `PIPELINE_ERROR_READ: FFmpegDemuxer: data source error`。不是仅按文件后缀推测编码原因。
- 应用原先截取并定位输入流，WebView 又按请求范围定位，造成重复跳过。现在保留完整文件流交给 WebView 定位，响应范围信息仍对应请求；有限流的 `available/skip` 同时遵守剩余字节边界。相同失败样本修复后播放、非零范围读取及双向拖动通过；H.264 faststart、HEVC Main 10/AAC 样本也通过。参考 [Chromium 输入流加载实现](https://chromium.googlesource.com/chromium/src/+/4c509b812ed32980debbc54195ad5bb07f9ff670/android_webview/browser/network_service/android_stream_reader_url_loader.cc)。
- 原生 Instrumentation 通过：录像 Intent、私有 MP4 URI 读写授权及 MIME、流式暂存提交、取消／空录像清理、返回 URI 回退，以及 WebView 仅定位一次的流行为。系统相机由 ActivityMonitor 拦截并写入样本，未验证小米相机实际界面和录像编码。
- 录像按钮的网页文件选择、原生桥接录像／取消／暂存提交、视频保存播放、ZIP 往返、复制和删除独立性检查通过；原生适配 Node 专项 5 项通过。
- 专项脚本 `prototype/tests/android-video-playback.mjs` 使用专用模拟器和 `.tools` 中的三类生成视频，检查真实 WebView 非零 Range 响应、播放及前后拖动，播放过程不修改记录。验证结果及安装包见 `artifacts/verification.json` 与 `artifacts/看房日记-0.1.5-debug.apk`。
